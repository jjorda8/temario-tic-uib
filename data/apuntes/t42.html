1. Sintaxis y operadores

  • Java es un lenguaje orientado a objetos, compilado a bytecode (.class) que ejecuta la JVM (máquina virtual), lo que lo hace multiplataforma ("write once, run anywhere"). Gestión automática de memoria con recolector de basura. JDK (desarrollo) y JRE (ejecución). Versiones LTS recientes: 17, 21 y 25.
  • Tipos primitivos (8): byte (8 bits), short (16), int (32), long (64), float (32), double (64), char (16, Unicode), boolean. El resto son tipos referencia (objetos, arrays, String). Clases envoltorio (Integer, Double...) y autoboxing.
  • Operadores: aritméticos (+ − * / %), incremento (++ −−, prefijo y sufijo), relacionales (== != < >), lógicos (&& || ! con cortocircuito), a nivel de bit (& | ^ ~ << >> >>>), asignación compuesta (+=), ternario (c ? a : b), instanceof.
  • Con objetos, == compara referencias y equals() compara contenido (por ejemplo, en String).
  • Conversiones: implícitas (de menor a mayor rango) y explícitas con cast. var para inferencia de tipos locales (Java 10).

2. Estructuras de control

  • Condicionales: if / else if / else, switch (también con String y enum; switch como expresión con -> desde Java 14).
  • Bucles: for, for-each (for (T x : coleccion)), while, do-while (se ejecuta al menos una vez).
  • Saltos: break, continue, return, etiquetas.

3. Orientación a objetos

  • Clase (plantilla) y objeto (instancia creada con new). Atributos, métodos y constructores (mismo nombre que la clase, sin tipo de retorno; this(...)).
  • Encapsulación con modificadores de acceso: private (solo la clase), sin modificador o package-private (el paquete), protected (paquete y subclases), public (todos). Getters y setters.
  • static (de la clase, no de la instancia), final (constante; método no sobrescribible; clase no heredable), abstract.
  • Sobrecarga (mismo nombre, distintos parámetros; en compilación) frente a sobrescritura (redefinir un método heredado con la misma firma; anotación @Override; en ejecución).
  • Polimorfismo: una referencia de tipo padre puede apuntar a objetos hijos y se ejecuta el método del objeto real (enlace dinámico).
  • Clase abstracta (no se instancia; puede tener métodos abstractos y concretos y estado) frente a interfaz (contrato; métodos abstractos, default y static; una clase puede implementar varias).
  • Otros: clases internas y anónimas, enum, record (Java 16, clases de datos inmutables), clases selladas (sealed), lambdas e interfaces funcionales (Java 8), Streams.

4. Herencia

  • class Hija extends Padre: herencia simple de clases (una sola superclase); la múltiple solo existe a través de interfaces (implements A, B).
  • Todas las clases heredan de Object (equals, hashCode, toString, getClass...). Si se sobrescribe equals hay que sobrescribir hashCode.
  • super(...) llama al constructor del padre (debe ser la primera instrucción); super.metodo() llama a la versión del padre.
  • Los constructores no se heredan. Los métodos private y static no se sobrescriben.
  • Principio de sustitución de Liskov; preferir composición a herencia cuando no hay relación "es un".

5. Control de excepciones

  • Jerarquía: Throwable → Error (problemas graves de la JVM, como OutOfMemoryError; no se capturan) y Exception.
  • Checked (comprobadas): heredan de Exception pero no de RuntimeException (IOException, SQLException). El compilador obliga a capturarlas o declararlas con throws.
  • Unchecked: RuntimeException y subclases (NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException, IllegalArgumentException). No es obligatorio tratarlas.
  • try { } catch (TipoA | TipoB e) { } finally { }: finally se ejecuta siempre. Multi-catch desde Java 7. Los catch van de lo más específico a lo más general.
  • try-with-resources (Java 7): cierra automáticamente los recursos que implementan AutoCloseable.
  • throw lanza una excepción; throws declara que un método puede lanzarla. Excepciones propias heredando de Exception o RuntimeException.

6. Genéricos

  • Permiten parametrizar clases, interfaces y métodos con tipos: List<String>, class Caja<T>, <T> void metodo(T x). Seguridad de tipos en compilación y sin casts. Operador diamante new ArrayList<>().
  • Tipos acotados: <T extends Number>.
  • Comodines: <?>, <? extends T> (para leer, productor) y <? super T> (para escribir, consumidor): regla PECS.
  • Borrado de tipos (type erasure): la información genérica desaparece en tiempo de ejecución; no se pueden usar primitivos (List<int> no; List<Integer> sí).
  • Colecciones: List (ArrayList, LinkedList), Set (HashSet, TreeSet), Map (HashMap, TreeMap), Queue y Deque.

7. El patrón MVC

  • Modelo: datos y lógica de negocio. Vista: presentación al usuario. Controlador: recibe las acciones del usuario, actualiza el modelo y elige la vista.
  • Ventajas: separación de responsabilidades, reutilización, pruebas y trabajo en paralelo.
  • En Java web: Spring MVC (DispatcherServlet como controlador frontal, controladores con @Controller, vistas Thymeleaf/JSP), Jakarta EE (Servlets como controlador, JSP/JSF como vista). Variantes: MVP y MVVM.

Claves para el test

  • Herencia simple de clases; múltiple solo con interfaces.
  • Checked = obligatorio tratarlas (IOException); unchecked = RuntimeException.
  • finally se ejecuta siempre; try-with-resources cierra AutoCloseable.
  • Sobrecarga = parámetros distintos; sobrescritura = misma firma en la subclase.
  • protected = paquete + subclases. == compara referencias; equals, contenido.
