1. Conceptos

  • La automatización robótica de procesos (RPA, Robotic Process Automation) usa robots de software (bots) que imitan las acciones de una persona en las interfaces de las aplicaciones: hacer clic, escribir, copiar y pegar, leer pantallas, abrir correos, descargar ficheros.
  • No son robots físicos ni modifican los sistemas existentes: trabajan "por encima" de ellos (integración no invasiva, en la capa de presentación).
  • Procesos adecuados: repetitivos, de gran volumen, basados en reglas claras, con datos estructurados y digitales, estables (pocas excepciones y pocos cambios en las aplicaciones). Ejemplos: alta de datos entre sistemas sin integración, conciliaciones, generación de informes, comprobación de documentación, gestión de altas de usuarios.
  • Bots atendidos (se ejecutan en el puesto del usuario cuando este los lanza) y desatendidos (funcionan solos en servidores, programados o por eventos).

2. RPA frente a otras formas de automatizar

  • Integración por API o servicios web: más robusta y eficiente; es preferible cuando existe. La RPA se usa cuando no hay API o integrarla es muy costoso.
  • BPM o gestores de expedientes: rediseñan y orquestan el proceso completo; la RPA automatiza tareas concretas dentro de él.
  • Automatización inteligente o hiperautomatización: RPA combinada con IA (OCR inteligente o IDP para documentos, procesamiento del lenguaje, aprendizaje automático, process mining para descubrir qué procesos automatizar).
  • En la Administración, la actuación administrativa automatizada (art. 41 de la Ley 40/2015) exige determinar previamente el órgano competente para definir especificaciones, programar, mantener, supervisar y auditar el sistema, y el órgano responsable a efectos de impugnación; se firma con sello electrónico.

3. Ciclo de un proyecto

  1. Identificar y priorizar procesos (impacto, volumen, complejidad, estabilidad).
  2. Analizar y documentar el proceso (PDD: documento de definición del proceso); simplificarlo antes de automatizarlo.
  3. Diseñar y desarrollar el bot con la herramienta (grabadores, editores visuales de flujos, selectores de elementos, manejo de excepciones).
  4. Probar con datos reales y casos excepcionales.
  5. Desplegar en producción y supervisar con el orquestador (programación, colas de trabajo, registros, credenciales).
  6. Mantener: los cambios en las aplicaciones rompen los bots.

4. Beneficios, riesgos y gobierno

  • Beneficios: rapidez de implantación, reducción de errores y plazos, funcionamiento 24×7, trazabilidad y liberar al personal de tareas mecánicas.
  • Riesgos: fragilidad ante cambios de interfaz, automatizar procesos ineficientes, gestión de credenciales de los bots, proliferación sin control y deuda técnica.
  • Gobierno: centro de excelencia (CoE) que fija estándares, prioriza, controla la seguridad y la calidad; inventario de bots y responsables; cuentas de servicio con mínimo privilegio y credenciales en un almacén seguro; registro de las acciones para auditoría.

5. Herramientas

  • UiPath (Studio, Robot, Orchestrator), Microsoft Power Automate (flujos de escritorio y en la nube), Automation Anywhere, Blue Prism (SS&C), Appian, Pega.
  • Código abierto: Robot Framework con RPA Framework, OpenRPA, TagUI.
  • Scripts y herramientas de automatización clásicas (PowerShell, Python con Selenium o Playwright) para casos sencillos.

Claves para el test

  • RPA = robots de software que imitan acciones humanas en la interfaz.
  • Atendidos (en el puesto del usuario) frente a desatendidos (en servidor).
  • Procesos idóneos: repetitivos, de alto volumen y basados en reglas.
  • Si hay API, es mejor integrar por API que usar RPA.
