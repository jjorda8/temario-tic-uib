1. El modelo relacional

  • Propuesto por E. F. Codd (1970). Los datos se organizan en relaciones (tablas) formadas por tuplas (filas) y atributos (columnas) con un dominio de valores.
  • Claves: superclave, clave candidata, clave primaria (identifica cada fila; no nula y única), clave alternativa y clave ajena (foránea, referencia a la primaria de otra tabla).
  • Integridad: de entidad (la clave primaria no puede ser nula), referencial (las claves ajenas apuntan a filas existentes; acciones ON DELETE/UPDATE CASCADE, SET NULL, RESTRICT) y de dominio.
  • Álgebra relacional: selección, proyección, unión, diferencia, producto cartesiano, join.
  • Diseño: modelo entidad-relación (entidades, atributos, relaciones con cardinalidades 1:1, 1:N, N:M) y paso a tablas (las N:M generan una tabla intermedia).
  • Normalización: 1FN (valores atómicos), 2FN (sin dependencias parciales de la clave), 3FN (sin dependencias transitivas), FNBC (todo determinante es clave candidata). Se desnormaliza a propósito para rendimiento en análisis.

2. Características de un SGBD relacional

  • Independencia de los datos según la arquitectura ANSI/SPARC de tres niveles: externo (vistas de usuarios), conceptual (lógico) e interno (físico). Independencia lógica y física.
  • Transacciones ACID: atomicidad (todo o nada), consistencia (de un estado válido a otro), aislamiento (las transacciones concurrentes no interfieren) y durabilidad (lo confirmado persiste).
  • Niveles de aislamiento (SQL): READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ y SERIALIZABLE. Anomalías que evitan: lectura sucia, lectura no repetible y fantasmas.
  • Control de concurrencia: bloqueos (compartidos y exclusivos; protocolo de dos fases; interbloqueos) o MVCC (varias versiones de las filas, como en PostgreSQL y Oracle).
  • Seguridad (usuarios, roles, privilegios, cifrado), integridad, lenguaje declarativo (SQL), catálogo.
  • Recuperación: registro de transacciones (log de escritura anticipada, WAL), checkpoints, copias y recuperación a un punto en el tiempo.
  • Productos: Oracle, Microsoft SQL Server, PostgreSQL, MySQL/MariaDB, IBM Db2.

3. Componentes

  • Procesador de consultas: analizador (parser), optimizador (elige el plan de ejecución según estadísticas y costes; se consulta con EXPLAIN) y motor de ejecución.
  • Gestor de almacenamiento: ficheros de datos, páginas o bloques, buffer (caché en memoria), índices.
  • Gestor de transacciones y de concurrencia; gestor de recuperación con el log.
  • Diccionario de datos o catálogo: metadatos de tablas, columnas, índices, usuarios.
  • Índices: árboles B+ (los más comunes, búsquedas por rango), hash (igualdad), bitmap (pocos valores distintos), índices agrupados (clustered) y no agrupados. Aceleran las lecturas y penalizan las escrituras.
  • Otros objetos: vistas, procedimientos almacenados, funciones, disparadores (triggers), secuencias, sinónimos.
  • Alta disponibilidad: replicación, clústeres (Oracle RAC, Always On en SQL Server), log shipping.

Claves para el test

  • ACID: atomicidad, consistencia, aislamiento, durabilidad.
  • ANSI/SPARC: niveles externo, conceptual e interno.
  • SERIALIZABLE es el nivel de aislamiento más estricto.
  • 2FN elimina dependencias parciales; 3FN, transitivas.
  • Integridad referencial = claves ajenas válidas.
