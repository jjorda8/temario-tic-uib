1. Conceptos básicos de Windows Server

  • Ediciones de Windows Server (Standard, Datacenter) e instalación con escritorio o Server Core (sin interfaz gráfica, menor superficie de ataque).
  • Roles (AD DS, DNS, DHCP, servidor de archivos, IIS, Hyper-V, RDS, WSUS...) y características. Herramientas: Administrador del servidor, consolas MMC, Windows Admin Center y PowerShell (cmdlets Verbo-Sustantivo, remoting).
  • Sistema de ficheros NTFS (permisos, cifrado EFS, cuotas) y ReFS. Cifrado de disco con BitLocker.
  • Permisos NTFS (control total, modificar, lectura y ejecución, lectura, escritura) y de recurso compartido: se aplica el más restrictivo de los dos al acceder por red. Las denegaciones explícitas prevalecen.
  • Cuentas y grupos locales frente a cuentas de dominio. Control de cuentas de usuario (UAC).

2. Dominios y Directorio Activo (AD DS)

  • Active Directory Domain Services: servicio de directorio que centraliza identidades, equipos, recursos y políticas. Se basa en LDAP, Kerberos y DNS (los clientes localizan los controladores con registros SRV).
  • Estructura lógica: bosque (límite de seguridad, esquema y catálogo comunes) → árboles (dominios con espacio de nombres contiguo) → dominios (límite de replicación y administración) → unidades organizativas (OU; contenedores para delegar administración y aplicar GPO).
  • Estructura física: controladores de dominio (DC) con réplica multimaestro; sitios (ubicaciones con buena conectividad) que optimizan la replicación y la autenticación; DC de solo lectura (RODC) para sedes poco seguras.
  • Catálogo global: copia parcial de todos los objetos del bosque para búsquedas y para resolver la pertenencia a grupos universales.
  • Roles FSMO (5): de bosque, maestro de esquema y maestro de nombres de dominio; de dominio, maestro RID, emulador de PDC (hora, contraseñas, bloqueos) y maestro de infraestructura.
  • Relaciones de confianza entre dominios y bosques (transitivas o no, unidireccionales o bidireccionales).
  • Grupos: tipo seguridad o distribución; ámbito local de dominio (para asignar permisos a recursos), global (para agrupar usuarios del dominio) y universal (de todo el bosque). Estrategia AGDLP: cuentas → grupos globales → grupos locales de dominio → permisos.
  • Niveles funcionales del dominio y del bosque. Entra ID (antes Azure AD) para la nube, sincronizado con Entra Connect.

3. Directivas de grupo (GPO)

  • Conjunto de configuraciones de equipo y de usuario que se vinculan a sitios, dominios u OU.
  • Orden de aplicación LSDOU: Local → Sitio → Dominio → OU (de la más alta a la más anidada). La última aplicada prevalece si hay conflicto.
  • Herencia, bloqueo de herencia en una OU y exigido (enforced) en un vínculo, que gana al bloqueo. Filtrado por grupos de seguridad y filtros WMI. Preferencias frente a directivas.
  • Comandos: gpupdate /force (aplicar), gpresult /r (ver las aplicadas). Gestión con la consola GPMC.

4. Directivas de seguridad

  • Directivas de cuenta (en el dominio): contraseñas (longitud mínima, complejidad, historial, vigencia), bloqueo de cuentas (umbral, duración, restablecimiento) y Kerberos. Directivas de contraseña específicas (fine-grained) para grupos concretos.
  • Directivas locales: auditoría, asignación de derechos de usuario (inicio de sesión local, por red, como servicio...), opciones de seguridad.
  • Auditoría avanzada, registro de eventos y reenvío a un SIEM; firewall de Windows con seguridad avanzada; restricción de aplicaciones (AppLocker, WDAC); Microsoft Defender.
  • Buenas prácticas: modelo de niveles (tiering) para cuentas administrativas, LAPS (contraseña única y rotatoria del administrador local), grupo Usuarios protegidos, desactivar NTLMv1 y SMBv1, actualizaciones con WSUS o Intune, guías CCN-STIC de bastionado de Windows, configuración segura del ENS (op.exp.2).

Claves para el test

  • Bosque = límite de seguridad; dominio = límite de replicación y administración; OU = delegar y aplicar GPO.
  • LSDOU: local, sitio, dominio, OU.
  • 5 roles FSMO: 2 de bosque (esquema, nombres de dominio) y 3 de dominio (RID, emulador PDC, infraestructura).
  • Ámbitos de grupo: local de dominio, global, universal.
  • Entre permisos NTFS y de recurso compartido se aplica el más restrictivo.
