1. Conceptos fundamentales

  • El DNS es una base de datos distribuida y jerárquica que traduce nombres de dominio a direcciones IP (y otros datos). Definido en las RFC 1034 y 1035.
  • Usa el puerto 53: UDP para consultas normales y TCP para respuestas grandes y transferencias de zona.
  • Espacio de nombres en árbol: raíz (".") → dominios de primer nivel (TLD: genéricos como .com, .org; geográficos como .es; patrocinados) → segundo nivel (uib.es) → subdominios.
  • FQDN: nombre completo terminado en punto (www.uib.es.).
  • Zona: parte del espacio de nombres que administra un servidor; se puede delegar un subdominio a otros servidores mediante registros NS.
  • La gestión de .es corresponde a Red.es (disposición adicional sexta de la LSSI); la de la raíz, a ICANN/IANA.

2. Tipos de servidores

  • Servidores raíz: 13 identidades (A a M), replicadas en cientos de instancias con anycast.
  • Servidores de TLD.
  • Autoritativos: tienen la información oficial de una zona. El primario (maestro) tiene la copia editable; los secundarios (esclavos) la copian por transferencia de zona.
  • Recursivos (resolvers): resuelven las consultas de los clientes preguntando a otros servidores y guardan las respuestas en caché durante el TTL.
  • Solo caché y reenviadores (forwarders): pasan las consultas a otro servidor.
  • DNS dividido (split DNS): respuestas distintas para la red interna y para Internet.
  • Software habitual: BIND, Unbound, PowerDNS, Microsoft DNS (integrado en Active Directory).

3. Resolución de nombres

  • El cliente (stub resolver) consulta primero su caché y el fichero hosts, y después pide al resolver una consulta recursiva (quiere la respuesta final).
  • El resolver hace consultas iterativas: pregunta a la raíz, que le remite al TLD, que le remite al autoritativo, que da la respuesta.
  • Respuestas: autoritativa (del servidor de la zona) o no autoritativa (de caché). Respuesta negativa NXDOMAIN (no existe).
  • Resolución inversa: de IP a nombre con registros PTR en in-addr.arpa (IPv4) o ip6.arpa (IPv6).

5. Seguridad del DNS

  • Amenazas: envenenamiento de caché (cache poisoning), suplantación, ataques DDoS de amplificación, túneles DNS para exfiltrar datos, secuestro de dominios.
  • DNSSEC (RFC 4033-4035): firma los registros para garantizar autenticidad e integridad (no cifra). Cadena de confianza desde la raíz con registros DS.
  • DoT (DNS sobre TLS, puerto 853) y DoH (DNS sobre HTTPS, 443): cifran la consulta para proteger la privacidad.
  • Restringir las transferencias de zona (AXFR completa, IXFR incremental) a los secundarios autorizados (TSIG) y no ofrecer recursión abierta a Internet.

Claves para el test

  • Puerto 53: UDP para consultas, TCP para transferencias de zona.
  • Cliente → resolver: recursiva; resolver → servidores: iterativas.
  • MX = correo; PTR = inversa; CNAME = alias; SOA = datos de la zona; SRV = servicios.
  • DNSSEC autentica, no cifra. DoH/DoT cifran.
