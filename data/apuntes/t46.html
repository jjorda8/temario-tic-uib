1. Gestión de la configuración del software (GCS)

  • Disciplina que identifica, controla y registra los elementos de un proyecto de software y sus cambios a lo largo del ciclo de vida, para mantener su integridad y trazabilidad.
  • Elemento de configuración (ECS): cualquier producto bajo control (código, documentación, requisitos, scripts, configuración, bibliotecas).
  • Línea base: versión revisada y aprobada de un conjunto de elementos que solo se cambia mediante el procedimiento formal de control de cambios.
  • Actividades: identificación de la configuración, control de cambios (petición, evaluación de impacto, aprobación por un comité de control de cambios, implementación y verificación), registro del estado (contabilidad) y auditoría de la configuración (física y funcional).
  • Normas: IEEE 828, ISO/IEC/IEEE 12207; en ITIL, gestión de la configuración con la CMDB. En Métrica v3 es una interfaz (GC). En el ENS, gestión de la configuración (op.exp.3) y de cambios (op.exp.5).
  • Conceptos: versión, revisión, variante, release (entrega), rama, etiqueta. Versionado semántico MAYOR.MENOR.PARCHE (cambios incompatibles, nuevas funciones compatibles, correcciones).

2. Sistemas de control de versiones

  • Registran los cambios en ficheros a lo largo del tiempo, permiten volver a versiones anteriores, trabajar en paralelo y saber quién cambió qué.
  • Modelos: locales, centralizados (un repositorio en un servidor: CVS, Subversion) y distribuidos (cada copia es un repositorio completo con todo el historial: Git, Mercurial).
  • Modelos de concurrencia: bloquear-modificar-desbloquear y copiar-modificar-fusionar (el habitual).

3. Subversion (SVN)

  • Sistema centralizado de Apache, sucesor de CVS. Números de revisión globales y correlativos para todo el repositorio; commits atómicos.
  • Estructura convencional: trunk (línea principal), branches (ramas), tags (etiquetas). Ramas y etiquetas son copias baratas.
  • Comandos: svn checkout (obtener una copia de trabajo), update, add, commit (envía directamente al servidor), status, diff, log, merge, revert, copy (crear ramas o etiquetas), lock.
  • Necesita conexión con el servidor para la mayoría de operaciones; permite control de acceso por carpetas.

4. Git

  • Sistema distribuido creado por Linus Torvalds (2005). Guarda instantáneas identificadas por un hash (SHA-1, migrando a SHA-256), no diferencias.
  • Tres áreas: directorio de trabajo → área de preparación (staging o índice) → repositorio local (.git) → repositorios remotos.
  • Comandos: git init/clone, add, commit, status, log, diff, branch, switch/checkout, merge, rebase, fetch (descarga sin integrar), pull (fetch + merge o rebase), push, tag, stash, reset, revert (deshace creando un commit nuevo), cherry-pick.
  • Merge conserva la historia con un commit de fusión (o avance rápido, fast-forward); rebase reescribe la historia para dejarla lineal (no hacerlo en ramas ya compartidas).
  • Conflictos: cuando dos ramas cambian las mismas líneas; se resuelven a mano y se confirman.
  • Flujos de trabajo: GitFlow (main, develop, feature, release, hotfix), GitHub Flow (main + ramas cortas + pull requests), trunk-based development (integración continua en la rama principal). Revisión de código con pull/merge requests.
  • Plataformas: GitHub, GitLab, Bitbucket, Gitea. .gitignore para excluir ficheros.
