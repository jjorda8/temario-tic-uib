1. Lenguajes de marcas

Codifican un documento junto con etiquetas que describen su estructura o su presentación. Origen en SGML (ISO 8879); de él derivan HTML y XML. Se usan para intercambiar información entre sistemas de forma independiente de la plataforma.

2. XML (eXtensible Markup Language)

  • Recomendación del W3C (1998). Metalenguaje: permite definir lenguajes propios. Describe datos, no su presentación.
  • Estructura: prólogo (<?xml version="1.0" encoding="UTF-8"?>), un único elemento raíz, elementos anidados, atributos, texto, comentarios, secciones CDATA, instrucciones de procesamiento y entidades (&lt; &gt; &amp; &quot; &apos;).
  • Documento bien formado: cumple la sintaxis (una raíz, etiquetas cerradas y bien anidadas, sensible a mayúsculas, atributos entre comillas y sin repetir).
  • Documento válido: además es conforme a un esquema (DTD o XSD). Todo documento válido está bien formado, pero no al revés.
  • DTD: definición de tipo de documento (ELEMENT, ATTLIST, ENTITY); no usa sintaxis XML y tiene pocos tipos de datos.
  • XML Schema (XSD): escrito en XML, con tipos de datos (string, integer, date...), tipos simples y complejos, restricciones (facetas), cardinalidad (minOccurs, maxOccurs) y espacios de nombres. Alternativas: RELAX NG, Schematron.
  • Espacios de nombres (namespaces): evitan conflictos entre vocabularios (xmlns:prefijo="URI").
Tecnologías asociadas
  • XPath: lenguaje para seleccionar nodos (/raiz/elemento[@atributo='x'], // cualquier nivel).
  • XSLT: transformación de XML en otro XML, HTML o texto mediante plantillas. XSL-FO para presentación (PDF).
  • XQuery: consultas sobre XML.
  • Procesadores (parsers): DOM (carga todo el documento como árbol en memoria; permite navegar y modificar), SAX (basado en eventos, secuencial, poca memoria, solo lectura) y StAX (streaming en el que el programa pide los eventos, pull). En Java, JAXB para mapear XML a objetos.
  • Usos: SOAP y WSDL, ficheros de configuración, documentos ofimáticos (OOXML, ODF), RSS y Atom, SVG, firmas XAdES, y en la Administración las NTI de documento y expediente electrónico (esquemas XSD de intercambio).

3. JSON (JavaScript Object Notation)

  • Formato ligero de intercambio de datos basado en texto, derivado de la sintaxis de objetos de JavaScript. Especificado en el estándar ECMA-404 y en la RFC 8259 (UTF-8 obligatorio en intercambio).
  • Estructuras: objeto (pares nombre-valor entre llaves; los nombres siempre entre comillas dobles) y array (lista ordenada entre corchetes).
  • Tipos de valores: cadena, número, objeto, array, true, false y null. No admite comentarios, fechas como tipo propio, comillas simples ni comas finales.
  • JSON Schema: valida la estructura de documentos JSON (type, properties, required...).
  • Variantes y relacionados: JSON-LD (datos enlazados), GeoJSON, JSON Lines; consultas con JSONPath y jq; formatos binarios (BSON, CBOR); YAML (superconjunto más legible).
  • Uso principal: APIs REST, configuración, bases de datos documentales (MongoDB), tokens JWT.

Claves para el test

  • Bien formado = sintaxis correcta; válido = además cumple un esquema.
  • DOM carga todo en memoria; SAX funciona por eventos.
  • XSLT transforma; XPath selecciona.
  • JSON: claves entre comillas dobles; no admite comentarios.
